# git-py

Десктопный Git-клиент на Python с интерфейсом в духе GitKraken: граф коммитов,
рабочая директория, ветки, удалённые репозитории и история действий в одном окне.
Интерфейс построен на PySide6, Git-операции — на pygit2 и системном Git CLI.
Архитектура — MVVM + Command.

## Возможности

- **Граф коммитов:** цветные линии веток, метки веток и тегов, WIP и stash,
  поиск по SHA, сообщению и автору, подгрузка истории.
- **Рабочая директория:** stage/unstage файлов и отдельных строк diff,
  просмотр изменений, создание коммитов, игнорирование и сброс изменений.
- **Ветки и история:** создание, переименование, удаление, checkout,
  merge/rebase через меню и drag-and-drop, cherry-pick, revert,
  редактирование сообщения, drop и squash коммитов.
- **Конфликты:** панель конфликтующих файлов, диалог разрешения,
  продолжение и отмена merge/rebase, распознавание разрешения через внешний Git.
- **Удалённые репозитории:** clone, push/pull/fetch, управление remote,
  tracking-ветки с ahead/behind, опциональный автоматический fetch, настройка SSH-ключей.
- **Stash:** сохранение, применение, извлечение и удаление; работа с выбранными файлами.
- **Интерфейс:** вкладки репозиториев, встроенный терминал, панель истории действий,
  Undo/Redo для поддерживаемых команд, тёмная тема и сохранение раскладки окна.

Undo/Redo зависит от операции: push и fetch не откатываются кнопкой Undo,
а сброс к удалённой ветке не восстанавливает явно отброшенные незакоммиченные изменения.

## Требования

| Компонент | Назначение |
| --- | --- |
| Python 3.10+ | Запуск приложения |
| PySide6 ≥ 6.5 | Qt-интерфейс |
| pygit2 ≥ 1.12 | Доступ к Git через libgit2 |
| Git в `PATH` | Rebase, SSH-транспорт и вспомогательные Git-операции |
| OpenSSH (`ssh`, `ssh-keygen`) | SSH-подключения и генерация ключей, если они нужны |

Python-зависимости устанавливаются из [pyproject.toml](pyproject.toml).
GitPython упомянут в проектных документах как возможный fallback, но в текущие
зависимости не входит. CI проверяет проект на Ubuntu с Python 3.10, 3.11 и 3.12;
его конфигурация находится в [ci.yml](.github/workflows/ci.yml).

## Установка и запуск из исходников

Выполняйте команды из корня клонированного репозитория.

**Windows / PowerShell:**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m src.main
```

**Linux / macOS:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python -m src.main
```

Для запуска без инструментов разработки используйте `-m pip install -e .`.
Отдельная консольная команда `git-py` пока не объявлена; точка входа — `src.main`.

После запуска откройте существующий репозиторий через меню **File** или добавьте
вкладку кнопкой **+**. В **File → Settings…** доступны имя и email автора,
выбор SSH-ключей и использование глобальных настроек Git.

Для больших отправок через SSH увеличьте **General / SSH → Push timeout (SSH)**.
По умолчанию push может выполняться **1800 секунд (30 минут)** вместо 60 секунд;
допустимы значения от 1 до 86400 секунд (24 часа). Нажмите **OK** — настройка
сохраняется в `push_timeout_seconds` и применяется при следующем push без
перезапуска. Лимит охватывает всю операцию, включая упаковку и отправку данных.
Для HTTPS и остальных транспортов pygit2 этот таймаут не используется.

Во вкладке **AI** настраивается генерация сообщения коммита: URL, API key,
провайдер и модель. Нажмите на поле **Model**, чтобы загрузить список моделей,
затем **Test connection**, чтобы проверить ответ выбранной LLM. Через
**Edit prompts…** можно выбрать язык, применить пресет и отредактировать промпт.
После сохранения настроек добавьте файлы в staged и нажмите звёздочки справа
в **Commit Summary** — генерация заполнит summary и description.
Подробности и ограничения: [ИИ-сообщения коммитов](docs/AI_COMMIT_MESSAGES.md).

## Настройки

Настройки хранятся в пользовательском JSON-файле. Путь определяет
[`default_config_path()`](src/utils/config.py) через Qt `QStandardPaths`;
типичные пути — `%APPDATA%\git-py\config.json` в Windows и
`~/.config/git-py/config.json` в Linux.

Сохраняются размеры окна и панелей, ширина колонок графа, вкладки репозиториев,
горячие клавиши и параметры автора. Автоматический fetch по умолчанию выключен;
его интервал — 60 секунд. Граф первоначально загружает до 500 коммитов.
Ключи и значения по умолчанию приведены в [справочнике для агентов](docs/PROJECT_GUIDE.md).

## Проверки для разработки

После установки `.[dev]`, из корня проекта:

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check src/ tests/
Remove-Item Env:QT_QPA_PLATFORM
```

В Linux/macOS:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest
.venv/bin/python -m ruff check src/ tests/
```

`offscreen` нужен для тестов без графического экрана; перед обычным запуском
приложения уберите эту переменную. Тесты используют временные репозитории,
а сетевые сценарии — моки или локальные bare-репозитории.
Выборочные проверки и тестовые фикстуры описаны в [PROJECT_GUIDE.md](docs/PROJECT_GUIDE.md).

## Структура проекта

```text
src/
├── main.py         # точка входа
├── core/           # Git, модели, diff и раскладка графа; без Qt
├── viewmodels/     # состояние приложения, сигналы, команды и Undo/Redo
├── ui/             # главное окно, виджеты и диалоги
└── utils/          # конфигурация, тема, фоновые задачи и диагностика
tests/              # core/, viewmodels/, ui/, utils/
tools/              # скрипты диагностики графа
docs/               # справочник, проектные документы и история доработок
.github/workflows/  # CI
```
