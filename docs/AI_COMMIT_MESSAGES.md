# Генерация сообщения коммита

## Настройка

1. Откройте **File → Settings… → AI**.
2. Выберите провайдера или введите собственное имя. Для OpenAI, Ollama,
   LM Studio и OpenRouter предусмотрены стандартные URL. Пользовательский URL
   прокси не заменяется при смене провайдера.
3. Укажите OpenAI-совместимый API base URL и API key. Для локальных серверов
   без авторизации ключ можно оставить пустым. URL с `/v1` сохраняется;
   для URL без пути добавляется `/v1`. Поддерживаются собственные префиксы,
   например `/api/v1`, и вставка полного адреса `/chat/completions` или `/models`.
4. Нажмите поле **Model** или стрелку справа: список загружается в фоне.
   Можно ввести ID вручную, если сервер не поддерживает получение списка.
   Список содержит модели, возвращённые сервером; выберите модель для чата.
5. Нажмите **Test connection**. Проверка использует текущие, ещё не сохранённые
   значения формы и отправляет выбранной модели короткую просьбу ответить `OK`.
   Успех означает получение непустого ответа через Chat Completions.
6. Нажмите **Edit prompts…**, настройте сообщение и сохраните оба диалога через **OK**.
   **Cancel** в настройках отменяет также принятые в редакторе изменения промпта.

## Язык и пресеты

Язык находится над промптом и применяется к summary и description. Можно выбрать
русский, английский, немецкий, испанский, французский, китайский, японский или
ввести другой язык. По умолчанию используются русский и Conventional Commits.

| Пресет | Результат |
| --- | --- |
| Conventional Commits | `type(scope): summary`, краткие пункты в description; тип и scope остаются на английском |
| Plain / concise | Обычный заголовок в повелительном стиле, описание из 1–2 предложений |
| Detailed / review-friendly | Подробные пункты по затронутой функциональности и изменениям поведения |
| Git Flow | Conventional Commits с подсказкой по ветке: `feature/*`, `hotfix/*`, `bugfix/*`, `release/*`; приоритет у диффа |

Клик по пресету заменяет текст в редакторе; **Ctrl+Z** возвращает прежний текст.
Промпт после применения можно менять. Если текст отличается от всех пресетов,
стиль считается пользовательским. Служебное требование вернуть JSON с двумя
строковыми полями добавляется автоматически — вручную писать его не требуется.
Начальные блоки рассуждений `<think>…</think>` отделяются от итогового JSON,
включая JSON в Markdown-блоке. Это поддерживает стандартный ответ
[MiniMax через OpenAI API](https://platform.minimax.io/docs/api-reference/text-openai-api).
JSON из рассуждений не используется; ответ без завершённого итогового сообщения отклоняется.
Промпты не должны предписывать выдумывать номера задач, результаты проверок или
версию релиза: пресеты основываются на фактах из staged-диффа.

## Генерация

Добавьте изменения в **Staged Files** и нажмите звёздочки справа в **Commit Summary**.
Кнопка доступна при наличии staged-файлов; во время запроса показывает вращающийся
индикатор. Повторный запрос блокируется. Генерация заменяет оба поля черновиком,
который можно редактировать перед нажатием обычной кнопки **Commit**.

Источник — разница **HEAD → index**. При частичном staging учитываются только
индексированные изменения. Незакоммиченные правки working tree и untracked-файлы
не включаются. Первый коммит также поддерживается. Контекст собирается компактно:

- Удаление — имя файла и операция, без удалённого содержимого.
- Перемещение без изменения содержимого — старый и новый пути. Если файл при
  переносе отредактирован, дополнительно включается дифф правок, когда он помещается.
  Распознавание переносов не зависит от `diff.renames`; точные совпадения blob ID
  дополнительно сопоставляются без попарного сравнения содержимого.
- Изображения (в том числе текстовые SVG), RAW и другие бинарные ресурсы —
  только имя файла, операция и режим. Учитываются расширения распространённых
  ресурсов и проверка бинарного содержимого blob, включая неизвестные расширения.
- Для остальных файлов сначала резервируется место под полный список операций,
  затем добавляются патчи. Правки существующих файлов имеют приоритет перед полным
  содержимым новых. Непоместившийся патч заменяется явной пометкой
  `[Patch omitted: context size limit.]`; имя файла сохраняется.

Модель получает инструкцию не выдумывать содержимое файлов, представленных только
метаданными. Такое сообщение может быть менее подробным для очень больших правок.
В синтетической проверке 2026-09-08 перенос 1100 файлов сократился с 6 298 580
символов delete/add-диффа до 77 000 символов контекста (на 98,78%).

Если пользователь изменил текст, переключил репозиторий или ветку, изменился
индекс либо началась другая фоновая Git-операция, устаревший ответ не применяется.
При сетевой ошибке и некорректном ответе существующий текст сохраняется.
Сам запрос не создаёт коммит и не меняет index, HEAD или историю Undo/Redo.

## Передаваемые данные и ограничения

- Сервер получает компактный контекст staged-изменений, имя ветки, промпт и язык.
  Тест подключения не отправляет данные репозитория.
- API key скрыт в форме, но сохраняется **без шифрования в локальном config.json**,
  как часть настроек `ai`. Тела ошибок сервера и ключ не выводятся в сообщения
  об ошибках. HTTP-перенаправления не выполняются.
- По умолчанию таймаут запроса — 60 секунд, предел контекста изменений — 120 000
  символов. Патчи сокращаются описанным выше способом. Если даже список операций
  с именами файлов не помещается, генерация отклоняется с отдельной ошибкой.
  Для изменения лимитов доступны `ai.timeout_seconds` и `ai.max_diff_chars` в JSON.
- Требуются совместимые `GET /models` (необязательно при ручном вводе ID) и
  `POST /chat/completions`. Responses-only модели и нестандартная авторизация
  отдельными адаптерами пока не поддерживаются.
- Качество результата зависит от модели. Пустой, обрезанный или не соответствующий
  формату ответ не заменяет поля. Лимит контекста конкретной модели может быть
  меньше лимита диффа приложения.

Контракты: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create),
[OpenAI Models](https://developers.openai.com/api/reference/resources/models/methods/list),
[Ollama](https://docs.ollama.com/api/openai-compatibility),
[LM Studio](https://lmstudio.ai/docs/developer/openai-compat/tools),
[OpenRouter](https://openrouter.ai/docs/quickstart).

## Реализация и проверки

- `core/staged_diff.py`: независимый от Qt компактный контекст staged-изменений
  и fingerprint HEAD/index.
- `utils/ai_client.py`, `utils/ai_config.py`: HTTP-клиент, обработка ошибок и пресеты.
- `CommitPanelViewModel`, `AISettingsViewModel`: QRunnable, защита повторного
  запуска и проверка актуальности результата; применение результата в GUI-потоке.
- `AISettingsPanel`, `AIPromptsDialog`, `CommitPanel`: пассивные формы.
- `tests/core/test_staged_diff.py`, `tests/utils/test_ai_client.py`,
  `tests/viewmodels/test_ai_generation.py`, `tests/ui/test_ai_workflow.py`:
  реальные временные репозитории, локальный HTTP-сервер и управляемые фоновые запросы.

Внешние LLM и реальные ключи в автоматических тестах не используются.

Проверено 2026-09-06: 60 новых тестов; целевая выборка (ИИ, commit panel,
settings, config, theme, SSH setup, toolbar) — **214 passed**. Полный набор
покрыт двумя частями: **333 core + 1108 остальных = 1441 passed**.
Запуск: `.venv/Scripts/python.exe -m pytest -q` с `QT_QPA_PLATFORM=offscreen`,
`--basetemp` внутри `.venv` и `-p no:cacheprovider`. После ошибки владельца
рабочей копии legacy-тесты графа и остальные тесты повторно запущены через
`pytest.main()` с изолированным `GIT_CONFIG_GLOBAL` и поисковым путём global config
для pygit2. Временный конфиг содержал только точный `safe.directory` проекта
и тестового автора; настройки пользователя не изменялись. Ruff и
`git diff --check` прошли. Qt-превью настроек, редактора и панели проверены
в тёмной теме с Windows-шрифтами.

### Исправление совместимости MiniMax (2026-09-06)

Ошибка `The model returned an invalid commit message` воспроизведена на настроенной
MiniMax-M3 с искусственным диффом: перед корректным JSON модель возвращала
`<think>…</think>`. Клиент теперь отделяет завершённые начальные блоки рассуждений
до разбора JSON и не меняет буквальные теги внутри полей сообщения.
Проверено: **60 passed** в `test_ai_client.py`, `test_ai_generation.py` и
`test_ai_workflow.py`, включая 7 новых регрессионных случаев; Ruff без ошибок.
Ручной запрос к настроенной MiniMax-M3 после исправления успешно вернул summary
и description. Использовался только искусственный дифф, файлы проекта не отправлялись;
настройки подключения и ключ не изменялись.

### Повторная диагностика MiniMax на staged-диффе (2026-09-06)

После разрешения пользователя ошибка воспроизведена на настоящем staged-диффе
git-py (97 067 символов). В ответе с `finish_reason=stop` часть итогового JSON
оказалась в блоке рассуждений, а `content` обрывался внутри description. Одного
удаления `<think>` было недостаточно. Запрос с `reasoning_split=true` также мог
вернуть пояснения перед корректным итоговым JSON.

Для `api.minimax.io` клиент теперь запрашивает отдельное поле рассуждений,
а для `MiniMax-M3` дополнительно отключает рассуждения через
`thinking: {"type": "disabled"}`. Выбор провайдера **Custom** этому не мешает:
определяется адрес API. Другим серверам эти параметры не отправляются.
Параметры описаны в [документации MiniMax](https://platform.minimax.io/docs/api-reference/text-openai-api).
Инструкция формата просит экранировать угловые скобки в JSON, чтобы буквальные
теги из исходного кода не становились служебными маркерами ответа.

Парсер принимает завершённый итоговый JSON после пояснений или метки `json`,
с Markdown-ограждением или без него. Незавершённый JSON и промежуточные черновики
не восстанавливаются; ошибка указывает конкретную проблему формата без вывода
содержимого ответа. Поля по-прежнему должны быть непустыми строками, summary —
однострочным.

Проверено: **77 passed** в трёх целевых ИИ-наборах, включая 17 новых случаев;
Ruff и `git diff --check` без ошибок. Исправленный клиент с сохранёнными настройками
MiniMax-M3 успешно сгенерировал оба поля на том же staged-диффе; fingerprint
HEAD/index после запроса совпал. Настройки пользователя и ключ не менялись.
