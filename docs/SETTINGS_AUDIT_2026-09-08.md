# Аудит настроек git-py — 2026-09-08

**Обновление после исправлений (2026-09-08).** Подтверждённые проблемы 1–6 ниже
исправлены. Discard оставляет файл при превышении лимита копии; JSON проходит
нормализацию типов и диапазонов; рабочие параметры передаются из конфигурации
окна; колонки графа сохраняются для своего репозитория; отказ записи позволяет
отменить закрытие или закрыть без сохранения. Также устранена коллизия общего
`.tmp` при пересекающихся сохранениях. Добавлены 42 регрессионных сценария,
обновлены PROJECT_GUIDE и чек-лист этапа 9.

Проверен весь набор из **1625 тестов** на окончательном коде: **1609 passed** в
полном прогоне и **16 passed** при повторе упавших случаев в коротком временном
каталоге Windows. В этих 16 случаях длинные пути вызывали ошибки Git CLI;
изменений кода между прогонами не было. Полный прогон выполнен вне песочницы,
поскольку тесты `test_visual_feat_regression.py` читают рабочий репозиторий и
в песочнице не проходят проверку владельца pygit2. В ходе проверки исправлена
изоляция старого теста auto-fetch: он оставлял активный таймер и мешал последующим
асинхронным сценариям. Ruff и `git diff --check` прошли.

Ниже сохранён исходный аудит: номера строк относятся к состоянию до исправлений,
предложения по расширению Settings остаются планом дальнейшего развития этапа 9.

Проверена текущая рабочая копия, включая незакоммиченные изменения. Фокус —
конфигурация, её применение в ViewModel, сохранение состояния интерфейса и
параметры, которые полезно сделать доступными пользователю. Это не полный
аудит всех Git-операций. Исходный код и существующие изменения не изменялись.

Главный вывод: прежде чем расширять Settings, нужно исправить применение и
валидацию уже объявленных параметров. Наиболее серьёзная проблема — лимит
резервной копии Discard незаметно превращает операцию в необратимую.

**Подтверждённые проблемы, по приоритету**

1. **[P1] Discard удаляет новый файл больше лимита без рабочего Undo.**
   `discard_file_max_backup_bytes` по умолчанию равен 1 МиБ. При превышении
   команда удаляет untracked-файл, не сохраняя содержимое; `_backup_exceeded`
   нигде не используется для уведомления или изменения доступности Undo.
   Команда попадает в историю, а `undo()` молча возвращается без восстановления.
   Проверено на файле размером 1 048 577 байт во временном репозитории с начальным
   коммитом: после Discard `can_undo=True`, после Undo файл отсутствует, ошибок нет.
   Контекстное действие файла вызывает ViewModel напрямую.
   Места: `src/viewmodels/commands.py:1784`, `:1789`, `:1797`;
   `src/viewmodels/main_viewmodel.py:1185`; `src/ui/widgets/commit_panel.py:540`.
   Исправление: при превышении лимита памяти сохранять копию на диск либо
   отклонять операцию до удаления. Если предусмотрено окончательное удаление,
   явно обозначать это до выполнения и не обещать Undo. Одного поля настройки
   размера резервной копии недостаточно.

2. **[P2] Авто-fetch и порог фонового merge не получают значения из JSON.**
   `MainWindow` передаёт `config_path`, но `MainViewModel` оставляет
   `auto_fetch_enabled`, `auto_fetch_interval_ms`, `merge_async_threshold`
   равными аргументам по умолчанию. Чтения этих ключей из конфигурации и вызова
   сеттеров из окна нет. Проверка с `true`, `1234`, `7` дала соответственно
   `False`, `60000`, `50`. Значение `auto_fetch_enabled=true` не включает таймер
   даже после перезапуска приложения.
   Места: `src/ui/main_window.py:134`; `src/viewmodels/main_viewmodel.py:123`,
   `:181`, `:185`; объявление ключей — `src/utils/config.py:68`.
   Исправление: загрузить и проверить значения до создания ViewModel, передать
   явно; после сохранения Settings применять соответствующие изменения.

3. **[P2] Корректный JSON с неверными типами вызывает исключения в UI.**
   `load_config()` проверяет только тип корневого объекта и объединяет словари.
   Воспроизведены: `diff_view_mode=[]` → `TypeError` при проверке принадлежности
   множеству; `recent_repos=[123]` → `TypeError` при восстановлении вкладок;
   `author_name=123` → `TypeError` при создании Settings. Файл с невалидным UTF-8
   вызывает необработанный `UnicodeDecodeError`. Также `get_int()` не проверяет
   диапазоны: `graph_history_limit=0` принимается, хотя Core возвращает при нём
   пустую историю, а размер страницы подгрузки остаётся нулевым. Последний
   сценарий установлен по коду, без отдельного прогона интерфейса.
   Места: `src/utils/config.py:160`, `:183`, `:315`;
   `src/ui/dialogs/settings_dialog.py:192`;
   `src/viewmodels/repo_tabs_viewmodel.py:159`;
   `src/viewmodels/graph_viewmodel.py:90`, `:164`;
   `src/core/repository.py:528`.
   Исправление: общая схема с типами, enum и границами; нормализация каждого
   поля с понятной диагностикой и сохранением исправных/неизвестных ключей.

4. **[P2] Переданный `config_path` не распространяется на все компоненты.**
   Автор, SSH и AI используют путь окна, но GraphViewModel, CommandProcessor
   и DiscardFileCommand самостоятельно вызывают `default_config_path()`.
   Проверка: в конфигурации окна история графа равна 17, Undo — 9; в отдельной
   конфигурации по умолчанию эти поля отсутствуют. Фактически получены 500 и 100.
   Это ломает изоляцию тестов и использование другого файла настроек; обычный
   запуск с единственным стандартным файлом эту проблему маскирует.
   Места: `src/viewmodels/main_viewmodel.py:137`, `:143`;
   `src/viewmodels/graph_viewmodel.py:81`;
   `src/viewmodels/commands.py:132`, `:1785`.
   Исправление: один источник настроек с явно передаваемыми значениями.
   Команды получают снимок параметров при создании, а не ищут глобальный файл.

5. **[P2] Ширины колонок графа перепутываются между вкладками репозиториев.**
   `graph_configs` читается только при восстановлении окна; запись делается
   только для активного репозитория при закрытии. Переключение вкладки не
   сохраняет ширины предыдущего репозитория и не восстанавливает следующий.
   Воспроизведение: A имел разделители `[260, 400]`, B — `[320, 500]`.
   После изменения A на `[280, 440]` и перехода к B остались `[280, 440]`.
   Закрытие записало эти размеры для B, изменения A потерялись.
   Проверка использовала два временных Git-репозитория; фоновое открытие
   подменено, чтобы изолировать именно переключение и сохранение колонок.
   Места: `src/ui/main_window.py:293`, `:1456`, `:1525`.
   Исправление: сохранять размеры предыдущей вкладки и применять размеры новой
   после успешного переключения; нормализовать ключ пути единообразно.

6. **[P2] Ошибка сохранения настроек прерывает обработку закрытия окна.**
   `closeEvent()` вызывает `save_config()` без обработки ошибки. При недоступном
   диске/отказе доступа исключение выходит из Qt-обработчика, а расположенные
   после записи закрытие терминала и вызов базового обработчика не выполняются.
   В проверке запись подменена на `PermissionError`: исключение вышло наружу,
   `TerminalWidget.close()` не вызван. Это отличается от SettingsDialog,
   который уже обрабатывает `OSError` и оставляет форму открытой.
   Место: `src/ui/main_window.py:1533`.
   Исправление: сообщать об ошибке сохранения и явно управлять результатом
   закрытия; гарантировать очистку ресурсов при фактическом закрытии.

**Что имеет смысл вынести в интерфейс настроек**

Приоритет означает очерёдность реализации, а не серьёзность дефекта.
Имена новых разделов и параметров ниже — предложение, а не существующий API.

| Очерёдность | Раздел | Предложение и причина |
| --- | --- | --- |
| 1 | Git / сеть | Авто-fetch и интервал; remote по upstream/выбору пользователя; отдельные таймауты сетевых транспортов. Сейчас авто-fetch жёстко выбирает `origin` и пропускает dirty worktree (`main_viewmodel.py:3010`) |
| 1 | Интерфейс | Шрифт и размер текста диффа/терминала, масштаб/плотность графа. Сейчас `Consolas, 10` зашит в `diff_view_widget.py:614`, `terminal_widget.py:298`; размеры графа — `graph_panel.py:109` |
| 1 | Терминал | Исполняемый файл shell, аргументы, история вывода. На Windows всегда запускается `cmd.exe`, максимум 2000 блоков вывода (`terminal_widget.py:149`, `:195`) |
| 1 | Горячие клавиши | Единый реестр действий и редактор `QKeySequenceEdit`; поиск конфликтов; сброс и отключение. Сейчас пустая строка восстанавливает default (`config.py:294`) |
| 1 | Сессия и папки | Восстанавливать вкладки или открывать пустое окно; каталог клонирования; последние каталоги открытия; сброс расположения панелей |
| 2 | AI | Таймаут и размер отправляемого контекста; профили серверов; исключения путей из отправки; показывать факт сокращения контекста. Для профиля репозитория полезнее язык и стиль сообщения |
| 2 | Diff | Размер шрифта, табуляция, перенос строк, количество строк контекста; поведение пробелов при просмотре. Изменение пробелов должно сохранять корректность сопоставления строк staging |
| 2 | Темы | Dark/light/system, общие цвета diff и графа, доступная палитра веток. Цвета diff сейчас отдельные `QColor`, палитра веток — `core/graph_v2.py:43`; одного переключения QSS недостаточно |
| 2 | Профиль автора | «Использовать настройки Git репозитория» и «Переопределить в приложении», итоговые имя/email. Сейчас helper читает только `git config --global`, локальный профиль не участвует (`config.py:394`) |
| 3 | Дополнительно | Начальная порция истории, лимит Undo и политика резервных копий; расширенные лимиты отображения только с разумными границами |

Для авто-fetch сначала стоит пересмотреть правило пропуска при dirty worktree:
пользователь как раз может долго работать без коммита и всё равно ожидать
обновления remote refs. Это изменение поведения требует отдельного решения и
проверки; нет смысла автоматически превращать каждое условие в переключатель.

Стратегия merge из UI (`no_ff=True`) закреплена правилами проекта. Вынос
«merge/fast-forward» или стратегии pull в Settings возможен как отдельная
функция с обновлением контрактов и Undo/Redo, но не как механическая замена
константы. Стандартные Git-параметры также желательно сначала наследовать из Git.

**Улучшения устройства настроек**

- Один `SettingsStore` загружает документ, проверяет схему и выдаёт типизированные
  разделы. ViewModel получает их явно, Core — только нужные значения обычных
  Python-типов. Не добавлять чтение Qt-конфига в Core.
- Разделить пользовательские предпочтения, состояние сессии и секреты. Можно
  начать с отдельных секций одного JSON, не вводя сразу несколько файлов.
  Ширины панелей и активная вкладка должны сохраняться автоматически, а не
  превращаться в числовые поля Settings.
- Ввести `schema_version` и последовательные миграции. Сохранять неизвестные
  ключи, поддержать вложенное объединение defaults. При повреждённом файле
  оставлять диагностируемую копию вместо его бесшумной замены defaults на выходе.
- После OK/Apply отправлять сигнал изменения с перечнем затронутых ключей.
  Интервалы, сочетания и оформление применять сразу; параметры Git-команды
  фиксировать при её создании; shell менять со следующего запуска терминала.
  Сейчас `MainWindow._open_settings_dialog()` только вызывает `exec()`
  (`src/ui/main_window.py:1867`). Автор, SSH и AI работают за счёт перечитывания,
  общего механизма применения остальных параметров нет.
- Сделать отдельные пользовательские значения для репозитория там, где они
  полезны: автор, remote, SSH/AI-профиль, язык и стиль коммитов. Их можно хранить
  локально по нормализованному пути, не добавляя секреты в отслеживаемые файлы.
- API-ключ сейчас сериализуется в JSON как обычная строка, несмотря на
  `repr=False` у поля и маску в интерфейсе (`ai_config.py:59`, `:84`;
  `settings_dialog.py:214`). Использовать системное хранилище учётных данных
  с явным поведением при недоступности. Будущий экспорт по умолчанию исключает
  ключи и данные сессии; приватный SSH-ключ вообще не включается в экспорт.
- Добавить поиск, восстановление defaults для раздела, импорт с предварительной
  проверкой и показом изменений. Показать путь файла настроек и происхождение
  эффективных значений. «Use default Git Credentials» лучше переименовать:
  сейчас этот флажок управляет авторством, а не сетевой аутентификацией.
- Учесть несколько экземпляров приложения. `save_config()` использует общее
  имя `config.json.tmp` (`config.py:198`); пересекающиеся записи конфликтуют.
  Искусственное перекрытие двух сохранений воспроизвело `PermissionError` на
  Windows. Нужны уникальные temp-файлы и согласованное чтение/изменение/запись;
  одна атомарная замена не предотвращает потерю изменений другого экземпляра.
- Генерация SSH-ключа немедленно сохраняет выбранные пути даже при последующем
  Cancel. Это документированный и протестированный контракт, не новый баг
  (`settings_dialog.py:247`). Интерфейс должен прямо обозначать немедленную
  активацию; менять контракт незаметно нельзя.

Не стоит выносить в обычный Settings задержки spinner/debounce, число потоков
мутаций, технические размеры hitbox и enum типов ячеек графа. Это детали
реализации и инварианты. Цвета следует объединять в тему, а масштабы — задавать
небольшим числом согласованных параметров. Ограничения диффа 20000 строк,
1000000 символов и 4000 символов на строку полезнее оформить как ограниченные
профили производительности, если для них появится реальный пользовательский
сценарий, сохранив защиту от зависания.
