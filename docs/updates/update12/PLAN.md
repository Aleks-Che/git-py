# PLAN update12 — всегда дополнять имя репозитория к пути клонирования

Дата: 2026-08-30. Источник: пользовательский фидбек после update11.

Контекст: пользователь указал путь `C:\work\git\my-repos`, склонировал
`git@github.com:Aleks-Che/git-py.git`. Clone прошёл успешно, но репозиторий
оказался прямо в `C:\work\git\my-repos`, а не в подпапке `git-py/`.

Причина: в update11 я сделал логику "если путь существует — оставляем
как есть". На Windows пользователь мог **заранее создать** `my-repos`
(или она уже была от других проектов), и мой код решил "раз папка
существует — пользователь хочет клонировать именно в неё". Это
оказалось неверной интерпретацией желания пользователя.

Ожидаемое поведение (как в большинстве Git GUI клиентов — GitHub Desktop,
Sourcetree, GitKraken): путь который указывает пользователь — это
**родительская директория** для нового клона. Имя репозитория всегда
добавляется в конец.

## Задачи

### 1. Упростить `_resolve_clone_target` в `CloneDialog`
- **Всегда** дополнять имя репозитория (если URL парсится и путь не
  заканчивается на это имя).
- Убрать проверку `target.exists()` — она вызывала неправильное поведение.
- Оставить только две проверки:
  1. Если URL не парсится — оставляем путь как есть.
  2. Если последний сегмент пути уже совпадает с именем репозитория —
     не дублируем.

### 2. Обновить тесты
- `test_clone_dialog_does_not_touch_existing_path` — теперь
  **противоположное** поведение: существующий путь тоже дополняется.
  Переименовать в `test_clone_dialog_appends_repo_name_to_existing_path`.
- Остальные тесты остаются в силе (prepend/non-exist/non-duplicate).

## Этапы
- **Stage A:** Изменить логику `_resolve_clone_target`.
- **Stage B:** Обновить тест.
- **Stage C:** STATUS-stage-1.md, merge feature/update12 → main, push.

## Технические заметки
- Изменение очень простое, но UX-критичное.
- Альтернатива (preference dialog "клонировать в эту папку или создать
  подпапку?") — overkill для одного параметра.
- Стандартные Git GUI клиенты всегда создают подпапку. Это "правильное"
  поведение для большинства пользователей.
